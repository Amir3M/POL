# Arman VPN upstream audit

## Baseline

The existing POL repository started at `0ea7d382c94c7a1a1870de6e9b8d3d7226ccbcb3` with its own README and GPL license. The configured `upstream` remote points to Arman VPN. The baseline is upstream's stable release `v1.0.19`, commit `492dd7f389c539790cde3d07167535d28788a0d0`. The findings below describe that source. Build and test outcomes are recorded in [TEST_REPORT.md](TEST_REPORT.md). ## Service access and privacy

- The source uses Firefox Accounts with a hard-coded OAuth client ID that Mozilla registers to Firefox desktop and with Mozilla's documented VPN authorization scope. Its Android browser sign-in embeds Mozilla's page and forwards an account session from a WebView bridge to the Go core. A second path accepts a password and email verification code in the application. Tokens refresh in the core, which classifies permanent credential rejection as requiring reauthentication. The manifest registers no Android OAuth redirect. A POL application ID therefore has no current manifest callback dependency, but any approved OAuth client may require registering a native redirect. Keep the Kotlin package and native JNI binding aligned. [FxA client](https://github.com/armanlife/arman-vpn-client/blob/v1.0.19/core/internal/fxa/fxa.go) · [Firefox OAuth client registration](https://mozilla.github.io/ecosystem-platform/fxa-sitemap/flow-oauth-relying-party) · [VPN scope](https://mozilla.github.io/ecosystem-platform/relying-parties/how-tos/firefox-browser-services) · [Sign-in orchestration](https://github.com/armanlife/arman-vpn-client/blob/v1.0.19/core/internal/service/signin_flow.go) · [Android manifest](https://github.com/armanlife/arman-vpn-client/blob/v1.0.19/app/android/app/src/main/AndroidManifest.xml)
- The core persists multiple accounts and restores access and refresh tokens from private files. POSIX permissions and Android app sandboxing protect those files. This storage has no Android Keystore-backed encryption. The password path can persist an encrypted password with an adjacent decryption key. Upstream's explicit account backup can carry both credentials and that key, and Android's automatic backup rules do not exclude these account files. POL's authorized flow must use a provider-approved sign-in contract, remove app password collection, protect tokens with platform-backed storage and exclude credentials from backups and diagnostics. [Account storage](https://github.com/armanlife/arman-vpn-client/tree/v1.0.19/core/internal/accounts) · [Core backup](https://github.com/armanlife/arman-vpn-client/blob/v1.0.19/core/internal/service/backup.go) · [Android backup rules](https://github.com/armanlife/arman-vpn-client/blob/v1.0.19/app/android/app/src/main/res/xml/data_extraction_rules.xml)
- The control plane uses Firefox Accounts, Guardian and Mozilla Remote Settings. The data plane uses Fastly-backed proxy endpoints and supports HTTP/1.1, HTTP/2 and HTTP/3 transports. An optional personal API relay can receive sign-in and token-bearing requests. The shared Guardian fallback setting defaults on, but the public source stub supplies no authorization for the shared pool. A private build profile can supply that authorization. Upstream update manifests and mirrors can also deliver announcements, and routing lists and missing country flags can contact third-party hosts. POL needs an independent update source and explicit authorization for any Mozilla integration or relay that it enables. [Guardian client](https://github.com/armanlife/arman-vpn-client/blob/v1.0.19/core/internal/guardian/guardian.go) · [Relay configuration](https://github.com/armanlife/arman-vpn-client/blob/v1.0.19/core/internal/service/network.go) · [Public profile stub](https://github.com/armanlife/arman-vpn-client/blob/v1.0.19/core/internal/evasion/evasion.go) · [Update manifest sources](https://github.com/armanlife/arman-vpn-client/blob/v1.0.19/app/lib/app_info.dart)
- Mozilla documents the Firefox Android VPN as protection for browsing inside Firefox. The separate Mozilla VPN subscription has its own service terms. Mozilla's Firefox Accounts documentation describes production integration on request for Mozilla groups, and Mozilla reported investigating possible abuse by unauthorized third-party apps. This audit found no authorization for POL to use the Firefox OAuth identity, VPN scope, Guardian proxy or Arman relay pool. An ordinary account is insufficient evidence of authorization. No live authenticated requests were used for this audit. [Firefox Android VPN](https://support.mozilla.org/en-US/kb/mobile-android-vpn) · [Production FxA integration](https://mozilla.github.io/ecosystem-platform/relying-parties/tutorials/integration-with-fxa) · [Mozilla Connect](https://connect.mozilla.org/t5/discussions/mozilla-s-double-standards-privacy-for-some-exclusion-for/m-p/146684) · [Mozilla services terms](https://www.mozilla.org/en-US/about/legal/terms/services/) · [Mozilla subscription terms](https://www.mozilla.org/en-US/about/legal/terms/subscription-services/)

## Quota

Guardian's parser recognizes unlimited quota only when a response includes `X-Quota-Unlimited: true`. Otherwise it requires valid limit, remaining and reset headers. Missing or malformed headers leave usage unknown. Structured quota data flows into account cards and current connection status. Upstream also keeps some raw quota headers for handling exhaustion and can automatically switch accounts near a configured threshold. That behavior needs review against an approved service contract. [Header parsing](https://github.com/armanlife/arman-vpn-client/blob/v1.0.19/core/internal/guardian/usage.go) · [Account state](https://github.com/armanlife/arman-vpn-client/blob/v1.0.19/core/internal/proxy/accounts.go) · [Connection status](https://github.com/armanlife/arman-vpn-client/blob/v1.0.19/core/internal/proxy/status.go)

“Firefox Accounts have unlimited data at the moment” is localized copy shown when every account with known usage reports unlimited. The predicate skips unknown accounts, so the message can overstate the result. The alternate banner falls back to 50 GiB when no positive allowance is known. Mozilla separately announced a temporary uncapped period for eligible Firefox browsing through January 31, 2027. That announcement does not establish quota for an independent client. Display known values per account, keep unknown and refresh failure distinct, and rely on approved service data for any reset date. [Account banner](https://github.com/armanlife/arman-vpn-client/blob/v1.0.19/app/lib/ui/accounts_page.dart) · [Mozilla quota announcement](https://blog.mozilla.org/en/firefox/built-in-vpn-unlimited-data/)

## Device verification still needed

The source routes both IPv4 and IPv6 through the TUN for included apps. Split tunneling excludes the VPN application's own traffic from the VPN, so the app's connections can reach upstream without looping. DNS sent to the TUN uses synthetic address mapping and separate proxy DNS handling. The default control-plane resolver can fall back to system DNS. Verify actual DNS and IPv6 behavior on physical Android, including private DNS, Wi‑Fi/mobile handoffs, always-on and lockdown, and configured bypass lists. CPU, memory, battery and long-running connectivity likewise require measurement.
