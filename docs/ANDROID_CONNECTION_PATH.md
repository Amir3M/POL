# POL Android connection path

The comparison uses Arman VPN `v1.0.19` (`492dd7f389c539790cde3d07167535d28788a0d0`) and the POL preview tag `pol-v0.1.1-preview` (`33dfaaca196cf9149fdd93a7de1b35e98a30c3f9`). The Go core, upstream Kotlin service files and Dart `lib/core` are identical at these revisions.

## Where the preview stops

- Android launches `com.polvpn.app.PreviewActivity`. The manifest removes internet and foreground-service permissions, leaves the VPN service unregistered and disables backup. The activity registers `pol/preview` for device information and local diagnostics export. [Manifest](../app/android/app/src/main/AndroidManifest.xml) · [PreviewActivity](../app/android/app/src/main/kotlin/com/polvpn/app/PreviewActivity.kt)
- The Android branch in Dart `main()` opens `AndroidPreviewApp` and returns before `runAndroid()`. The preview screen offers Diagnostics and About. The inherited Connect control and native `app/android` channel are therefore unreachable in this APK. [Dart entry point](../app/lib/main.dart) · [Preview screen](../app/lib/ui/android_preview.dart)

## Provider and session boundaries

- The inherited OAuth code sends Firefox Desktop's registered client identity and Mozilla's VPN scope during exchange and refresh. `AccountPool.passFor()` loads and refreshes the account session, then uses its access token to obtain a Guardian proxy pass. Guardian distinguishes invalid credentials from missing VPN entitlement. Android consent establishes the local tunnel interface. Traffic egress depends on this additional service authorization for POL. [OAuth implementation](../core/internal/fxa/fxa.go) · [Account pool](../core/internal/proxy/accounts.go) · [Guardian errors](../core/internal/guardian/errors.go) · [Mozilla OAuth client registry](https://mozilla.github.io/ecosystem-platform/fxa-sitemap/flow-oauth-relying-party)
- Arman's shared recovery relay uses a build-specific authorization hook. `configureAPIRelay()` leaves the shared pool disabled when `evasion.Authorize()` returns nil, as it does in the public source build. This removes the optional relay fallback. The direct path still needs the provider's approved client, entitlement and endpoints. [Relay configuration](../core/internal/service/network.go) · [Public build hook](../core/internal/evasion/evasion.go)
- Arman's daemon restores credentials from its own application data using `AccountPool.AuthFor()` and app-private credential files. The current POL preview has no sign-in path. No phone was attached to verify an existing POL session. A later authorized build should preserve its own package ID and certificate for an in-place update, restore only a POL-issued session and put new session tokens in Android Keystore-backed storage. A side-by-side APK installed under a different application ID has its own app data. [App data directory](../app/android/app/src/main/kotlin/com/arman/firefoxvpn/CoreService.kt) · [Account storage](../core/internal/accounts/store.go)

Once POL has an approved OAuth client, redirect, VPN scope and entitlement, reconnect the retained Android entry point in a separate test artifact. Keep the provider gate in the offline preview. Use interactive sign-in on the phone if its POL session needs renewal. The legacy account entry points and debug credential import need to stay out of the authorized session flow. [Upstream security and authorization findings](UPSTREAM_AUDIT.md)

## Verification

The local SOCKS5 integration test passed in HTTP/2 and HTTP/3 modes with provider fixtures. It handled 12 transfers per mode and retained an open echo stream across simulated OAuth and Guardian pass renewal. The Android Dart preview, Android core startup and controller suites passed all 12 tests. Go tests passed for the mobile bridge, daemon, proxy, TUN, Guardian and Firefox Accounts packages. No Android device was attached. An authorized phone test should close Arman, connect in POL, and upload and download a file in another app while confirming the VPN route. ## Direct Guardian first test

The branch initially compared at `bcbc33cfdb85dc780cddf28c76dcd9ec7046cfaf`. Its changes since the published tunnel-test tag `46c6e95fc0e1cc3d308f048cb8bc5a8186bf40fd` were documentation only. The owner confirmed TUN and 256 KiB in both directions on Android 15 ARM64. The second run confirmed session restoration and reconnection. The owner observed Arman report `Guardian reached route=direct profile=vendor (direct=200)`, an established HTTP/2 session and a passing connection test on the same device and network. The log establishes the Guardian route in that Arman run. The initial account sign-in route and the effect of its vendor profile need separate evidence.

| Stage | Source behavior and dependency |
| --- | --- |
| Sign-in and refresh | The inherited Android browser sign-in collects a Firefox session through a WebView bridge. Exchange and refresh use the inherited Firefox Desktop client identity and VPN scope. POL needs its own approved native-browser authorization, exact callback and refresh contract. [Browser bridge](../app/lib/ui/browser_signin.dart) · [OAuth code](../core/internal/fxa/fxa.go) · [Refresh](../core/internal/proxy/auth.go) |
| Guardian reachability and pass | The default origin is `https://vpn.mozilla.org`. The inherited account pool calls Guardian with an OAuth access bearer. A successful token response supplies a distinct proxy pass and may include quota headers. The inherited client supports activation and alternate paths after some refusals. POL's first direct test needs approval and current entitlement to request a pass with its own OAuth registration. [Guardian client](../core/internal/guardian/guardian.go) · [Account pool](../core/internal/proxy/accounts.go) · [Recovery](../core/internal/guardian/region_recovery.go) |
| HTTP/2 and traffic | The daemon selects an egress separately from Guardian. It instantiates the existing H2 proxy with that egress and uses a distinct bearer for CONNECT streams over TLS. The first live test requires an egress approved for POL, then a browser request that actually crosses TUN and receives a response. [Engine startup](../core/internal/service/engine.go) · [HTTP/2 implementation](../core/internal/proxy/upstream_h2.go) |

The public source selects the `base` profile, whose shared relay authorization and alternate-address hooks are empty. A user-configured relay and inherited recovery can still apply independently in the general upstream path. The optional private build profile can override profile behavior. Its code is absent from the public build, so the source cannot establish the TLS or routing differences present in the owner's Arman APK. The POL direct acquisition path uses standard TLS and stops after the direct result, including HTTP 451. [Base profile](../core/internal/evasion/evasion.go) · [Relay setup](../core/internal/service/network.go) · [Alternate transport](../core/internal/guardian/alternate.go)

The first missing input is the POL-specific native OAuth registration. Provide the approved public client ID, exact Android redirect URI and ownership, authorization/token endpoints and provider-required request encoding, scopes and refresh configuration. The Guardian side also needs provider confirmation that this registration and test account are entitled for the device-wide POL client, the permitted direct origin and H2 egress or authorized endpoint list. Use configuration metadata through the repository owner. The account signs in interactively on the phone. OAuth, live relay-free Android startup and provider requests stay gated while that contract is missing.
